# OpenTelemetry + Grafana LGTM: Quick Verification Guide

This guide gives you the exact, copy-paste steps to test and view **Logs (Loki)**, **Metrics (Prometheus)**, and **Traces (Tempo)** inside your Grafana Dashboard.

---

## 1. Quick Start (2 Steps)

### Step 1: Ensure the LGTM Docker Container is Running
```powershell
docker run -d --name lgtm -p 3000:3000 -p 4317:4317 -p 4318:4318 -e GF_AUTH_ANONYMOUS_ENABLED=true -e GF_AUTH_ANONYMOUS_ORG_ROLE=Admin grafana/otel-lgtm:latest
```
*(If already started, Grafana is ready at [http://localhost:3000](http://localhost:3000)).*

### Step 2: Start the Auto-Instrumented FastAPI Server
```powershell
cd c:\Workspace\FastAPI\fastapi_otel\2_auto_instrumentation
python run_server.py
```
*Note the port displayed in your terminal (usually `http://127.0.0.1:8001/docs` or `8000/docs`).*

### Step 3: Trigger Some Requests in Swagger UI
1. Open **`http://127.0.0.1:8001/docs`** (or `8000/docs`).
2. Execute **`GET /books/{book_id}`** (e.g., ID `1`).
3. Execute **`GET /search`** (e.g., query `Clean`).

## 2. How to Check in Grafana Explore

Open your browser to: **[http://localhost:3000/explore](http://localhost:3000/explore)**

At the top-left (next to `Outline`), use the data source dropdown to check each pillar:

```
[ Outline ]  [ Data Source Dropdown ▾ ]  ──> Select Tempo, Prometheus, or Loki
```

---

### A. Check TRACES (Tempo)

Traces display the end-to-end request lifecycle and execution timing of your FastAPI endpoints.

1. **Select Data Source**: Choose **`Tempo`**.
2. **Query Type**: Select **`Search`**.
3. **Filter**:
   - **Service Name**: `book-store`
4. **Run**: Click the blue **`Run query`** button (top right).
5. **View Waterfall**:
   - In the results table, click any returned **Trace ID** (e.g., `GET /books/{book_id}`).
   - An interactive, color-coded waterfall appears showing millisecond durations for each step.

---

### B. Check METRICS (Prometheus)

Metrics track numerical aggregations like request counts, active traffic, and response times.

1. **Select Data Source**: Choose **`Prometheus`**.
2. **Enter Query**: Switch to the **`Code`** tab and paste:
   ```promql
   http_server_duration_milliseconds_count
   ```
3. **Run**: Click the blue **`Run query`** button.
4. **What you see**:
   - A time-series chart showing total requests.
   - A breakdown table showing `http_status_code="200"`, `http_method="GET"`, and `service_name="book-store"`.

> **Other useful metrics queries:**
> - In-flight concurrent requests: `http_server_active_requests`
> - Total response size: `http_server_response_size_bytes_count`

---

### C. Check LOGS (Loki)

Loki stores text log lines generated by FastAPI and Uvicorn.

1. **Select Data Source**: Choose **`Loki`**.
2. **Enter Query**: Switch to the **`Code`** tab and paste:
   ```logql
   {service_name="book-store"}
   ```
3. **Time Picker**: Ensure top-right time range is set to **`Last 1 hour`** or **`Last 30 minutes`**.
4. **Run**: Click the blue **`Run query`** button.
5. **What you see**:
   - Real-time application log lines with timestamps and severity tags (`INFO`, `WARN`):
     - `Started server process [...]`
     - `Application startup complete.`
     - `Fetching book with ID: 1`

---

## 3. Power Feature: Split View (Side-by-Side)

1. In the top-right toolbar of the Explore page, click the **`[ ◫ Split ]`** button.
2. Configure:
   - **Left Screen**: **`Tempo`** (Trace waterfall)
   - **Right Screen**: **`Prometheus`** (Request count graph) or **`Loki`** (Logs stream)
3. You now have complete visibility across **Traces**, **Metrics**, and **Logs** on a single unified screen.
