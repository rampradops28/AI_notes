Executive Overview & Knowledge Map

A unified technical reference combining hands-on MCP server engineering, RAG pipelines, foundation models, and scientific AI frameworks.

Standard

Model Context Protocol (MCP)

Universal open protocol connecting AI models (Claude, custom LLMs) safely to external tools, databases, and enterprise REST APIs over stdio or SSE.

  • Host vs Client vs Server architectural separation.
  • JSON-RPC 2.0 structured function messaging.
  • Tools, Resources, Prompts, Sampling primitives.
Technique

Retrieval-Augmented Generation (RAG)

Empowers LLMs with private, real-time factual knowledge by converting documents into high-dimensional vector embeddings stored in vector databases.

  • Open-book exam analogy: Accurate grounding.
  • Chunking & Overlap: Semantic sliding window.
  • Vector Databases: ChromaDB, Milvus, Qdrant.
Engineering

Scientific AI & Simulation (KogneX)

Physics-aware engineering platform that accelerates high-fidelity simulations through AI surrogate models and physics-informed gates.

  • AI = Guess (Explore design space).
  • Physics = Check (Sanity rule verification).
  • Solver = Proof (OpenFOAM verification).
💡 The Critical Conceptual Distinction: MCP vs. RAG

MCP is a protocol/standard (how the AI connects to outside worlds).
RAG is an information retrieval technique (how documents are chunked, embedded, and retrieved).
Key insight: A RAG pipeline can be packaged inside an MCP server to give Claude Desktop a private semantic memory tool!

1. Model Context Protocol (MCP) Architecture

How the 4-part architectural model coordinates LLM reasoning with safe, sandboxed execution.

Role Separation

The 4 Core Architectural Roles

  • Host (Claude Desktop / Custom App): The user interface and security coordinator. Discovers servers and requests user approval.
  • LLM (The Brain): Analyzes prompts, reasons about tool schemas, and decides which tool to call with which arguments. The LLM never executes code!
  • MCP Client (`client.py` / Built-in): The postman that speaks JSON-RPC 2.0 to transmit commands between host and server.
  • MCP Server (`server.py`): The hands that actually execute SQL queries, file I/O, and REST API calls. The server never makes decisions!
Golden Rules

The 4 Inviolable MCP Rules

  • 1. LLM only decides, never executes: It outputs structured JSON requests.
  • 2. Server only executes, never decides: It runs Python code blindly when instructed.
  • 3. Host is the Postman & Guard: Enforces security confirmations before modifying actions.
  • 4. MCP servers never talk to each other: The Host coordinates multi-hop chaining between servers.
+-----------------------------------------------------------------------------------+ | CLIENT / HOST | | (e.g., Claude Desktop OR your custom client.py) | | | | +-----------------------+ +------------------------------------+ | | | LLM | | MCP Client | | | | (Brain / Reasoning) | | (Postman / Connector) | | | +-----------+-----------+ +------------------+-----------------+ | +---------------|---------------------------------------------|---------------------+ | | | | JSON-RPC 2.0 (stdio / SSE) | | +---------------|---------------------------------------------|---------------------+ | | | | | | +----------v----------+ | | | | MCP Server | | | | | (server.py) | | | | +----------+----------+ | | | | | | | | Local API / DB / Disk | | v | | | +---------------------+ | | | | External Resources | | | | | (GitHub, SQLite...) | | | | +---------------------+ | | | | | | SERVER ENVIRONMENT | +---------------+-------------------------------------------------------------------+

Communication Protocol: REST vs JSON-RPC

Property REST (Web APIs) JSON-RPC 2.0 (MCP Protocol)
Paradigm Resource-oriented (`/users/123/profile`) Procedure / Function-call oriented (`tools/call`)
HTTP Verbs GET, POST, PUT, DELETE, PATCH Standardized single POST or bidirectional pipe
Identifiers URL paths & query strings Method names (`name: "create_issue"`) + payload params
Ideal Use Case Public web endpoints, CRUD data retrieval Remote procedure calls, tool calling, internal agent IPC

2. The 4 MCP Primitives

Every capability an MCP server provides falls into one of these four standardized primitives.

[DO] Action

1. Tools (`@mcp.tool()`)

Active executable functions invoked autonomously by the LLM to perform business logic, query databases, or call REST APIs.

  • Caller: LLM decides dynamically.
  • Inputs: Dynamic arguments typed with Python type hints.
  • Side Effects: Can write, update, delete, or create.
  • Examples: apply_leave(), create_issue(), search_documents().
[READ] Context

2. Resources (`@mcp.resource()`)

Read-only reference data attached via custom URI protocols. Provides structured background information without side-effects.

  • Caller: Typically attached by the User via @ in chat.
  • Identifier: Custom URI scheme (e.g. leave://policy).
  • Side Effects: Pure read-only. Zero mutations.
  • Examples: github://user/profile, leave://records.
[GUIDE] Workflow

3. Prompts (`@mcp.prompt()`)

Pre-packaged, parameterized prompt templates that guide consistent workflows for common enterprise tasks.

  • Caller: User selects from UI menu.
  • Parameters: Variables supplied by user (e.g. employee_id).
  • Value: Standardizes answers and eliminates vague user prompts.
  • Examples: review_leave_request(employee_id).
[THINK] Bi-Directional

4. Sampling (`sampling/createMessage`)

Enables the MCP Server to ask the Host's LLM to generate text or perform reasoning in the middle of a tool execution.

  • Direction: Server → Host LLM.
  • Use Case: Multi-step summarization or autonomous validation.
  • Safety: User retains oversight over sub-sampling requests.

4. Retrieval-Augmented Generation (RAG) Fundamentals

Overcoming LLM memory boundaries and hallucination by grounding answers in private vector data.

Concept

The 3 Letters of RAG

  • R (Retrieval): Search 1,000+ document chunks and extract only the top 2-3 most relevant paragraphs.
  • A (Augmentation): Inject those paragraphs alongside strict anti-hallucination instructions into the prompt.
  • G (Generation): The LLM synthesizes a fluent, cited response based strictly on the injected context.
Mathematical Meaning

Vector Embeddings & Cosine Similarity

An embedding model converts text into high-dimensional decimal coordinates (e.g. 384 or 1536 floats).

  • Semantic Proximity: "Car" and "Automobile" have nearly identical vector coordinates.
  • Cosine Similarity (1.0 to -1.0): Measures the cosine of the angle between vectors (1.0 = identical meaning).
  • Distance Metric: ChromaDB uses distance (0.0 = closest match).
Storage

What a Vector DB Stores

Unlike SQLite which indexes text strings, Vector DBs (ChromaDB, Milvus, Qdrant) index geometry:

  • ID: Unique chunk identifier (chunk_12).
  • Document Text: The raw paragraph.
  • Embedding: Vector array [-0.04, 0.81, ...].
  • Metadata: Document origin, page numbers, timestamps.

5. Chunking Strategies, Overlap & Evaluation Metrics

How to partition documents effectively without destroying context boundaries.

Chunking Styles

3 Primary Chunking Approaches

  • Fixed-Size Chunking: Splits text by strict character or word count (e.g. 500 characters). Fast, deterministic, and widely used.
  • Semantic Chunking: Calculates embedding similarity between consecutive sentences; splits where coherence drops. High quality, higher compute cost.
  • Agentic Chunking: Uses an LLM to read the document and decide natural topical boundaries. Highest quality, but slower and expensive.
Sliding Window

The Role of Chunk Overlap

Standard practice: Overlap = 10% to 20% of chunk size (e.g., 50 characters overlap for a 500-character chunk).

  • The Problem: Cutting blindly splits key sentences in half, causing queries like "When was Ram promoted?" to lose the connection between the person and the date.
  • The Solution: Duplicated words act as a semantic bridge across chunk borders.

Production RAG Evaluation Metrics

Metric What It Measures Ideal Target / Purpose
Recall @ K How many of the total relevant documents were successfully retrieved within top K results. High coverage; ensure no vital facts are missed.
Precision @ K What fraction of retrieved chunks are actually relevant to the question. Minimize noise and keep LLM context clean.
Mean Reciprocal Rank (MRR) Reciprocal rank (1 / position) of the first relevant document. Critical for Q&A systems where only the top answer counts.
NDCG Normalized Discounted Cumulative Gain; weights relevance by position. Overall ranking quality; highly relevant items must appear first.

6. Advanced RAG Architectures & CAG

Beyond simple naive search: Multi-query, hierarchical, agentic workflows and semantic caching.

Architecture

Agentic RAG

An autonomous agent plans query execution, queries vector stores iteratively, evaluates intermediate facts, and performs multi-hop reasoning before delivering the answer.

De-noising

Multi-Query RAG

The LLM generates 3-5 variations of the user's initial question from different angles, queries the vector database for all variants, and deduplicates the retrieved chunks.

Enterprise Tree

Hierarchical RAG

Indexes corporate documents across an organizational hierarchy: /Company → /Division → /Department → /Team for multi-stage scoped routing.

Cost Optimizer

Cache-Augmented Generation (CAG)

Caches embeddings and generated answers for frequent queries. Solves the redundancy and latency cost of running identical vector searches repeatedly.

7. Foundation Models, Weights & Hyperparameters

Core definitions across modern LLMs, model families, weights, and inference settings.

Hierarchy

Model Classification

  • Small Language Models (SLM): Compact, efficient, highly capable on edge devices (e.g. Phi-4).
  • Large Language Models (LLM): Broad generalized capabilities across reasoning, code, and language (e.g. GPT-4, Claude Sonnet).
  • Frontier Models: The absolute bleeding edge of intelligence and benchmark capabilities (e.g. GPT-5, Claude Opus).
Weights

Open Weights vs. Closed Weights

  • Open Weights (Llama, Phi, DeepSeek): Model weights are publicly downloadable. Can be self-hosted, fine-tuned, and run on private air-gapped clusters.
  • Closed Weights (GPT-4, Claude, Gemini): Accessed exclusively via proprietary cloud APIs. No direct weight inspection; easier maintenance.
Hyperparameter Tuning

Understanding Temperature (0.0 to 2.0)

Controls output randomness by scaling probability distributions during token generation:

Temperature Range Behavior Recommended Task
0.1 – 0.3 Strictly deterministic, low variance, mathematically precise Code generation, SQL queries, JSON-RPC schema output
0.5 – 0.7 Balanced, factual yet natural fluency Business chatbots, technical documentation, Q&A
0.8 – 1.2 High creativity, diverse vocabulary, unexpected ideas Brainstorming, creative writing, marketing copy

8. Scientific AI & Simulation: The KogneX & BrahmX Platform

Engineering AI architecture integrating machine learning surrogates with high-fidelity physics solvers.

Core Definitions

Surrogate Models & OpenFOAM

  • Surrogate Model: A fast mathematical approximation trained to mimic expensive simulations (CFD / FEA), delivering millisecond predictions instead of hours-long calculations.
  • OpenFOAM: Leading open-source C++ computational fluid dynamics (CFD) solver package used in aerospace and automotive engineering.
The Triad Formula

Engineering Sanity Equation

AI = Guess  |  Physics = Check  |  Solver = Proof

  • AI proposes design variations rapidly.
  • Physics gates enforce conservation of mass, momentum, and boundary rules.
  • Solvers execute full-fidelity simulations to produce verified truth.
Lifecycle

The 4 Stages of KogneX

1. Explore: AI scans thousands of potential candidate geometries.
2. Validate: Physics checks whether proposals make physical sense.
3. Execute: Solvers (OpenFOAM) run high-fidelity verification.
4. Learn: Verified results are stored to refine future predictions.

9. System Architecture, Statelessness & Cloud DevOps

Design principles for scalable distributed systems, containers, and orchestration.

State Model

Stateful vs. Stateless Systems

  • Stateful: Server retains session context across multiple requests (e.g. database transactions, shopping carts). Requires sticky routing.
  • Stateless: Every incoming request is entirely isolated and independent (HTTP, serverless lambdas, vending machine analogy). Enables effortless horizontal scaling.
Cloud Containerization

Amazon EKS & Microservices

  • Microservices: Decoupled, independently deployable services communicating over lightweight protocols (REST / gRPC / JSON-RPC).
  • Amazon EKS (Elastic Kubernetes Service): Managed Kubernetes service automating cluster provisioning, worker node scaling, and control plane resilience on AWS.

10. MCP Final Certification Exam & Technical Archive

The 8 verified examination questions and responses evaluating practical MCP proficiency (Score: 74/80 - 92.5%).

Q1: Transport Protocol

stdio vs. SSE in Production

Question: Which transport to pick for cloud deployment across an office network?

Verified Answer: Use SSE (Server-Sent Events over HTTP). `stdio` is limited to local child processes on the same physical host; SSE runs over HTTP, enabling access via Docker containers and cloud URLs.

Q2: Schema Design

Docstrings & Type Hints

Question: Why are docstrings and type hints mandatory for `@mcp.tool()`?

Verified Answer: Docstrings instruct the LLM on tool intent and context. Type hints are auto-compiled by MCP into formal JSON Schemas, guaranteeing the LLM supplies properly typed arguments and knows mandatory vs. optional parameters.

Q3: Primitives

Tool vs. Resource

Question: Main difference and who invokes each?

Verified Answer: Tools are executable actions called autonomously by the LLM to perform logic or state changes. Resources are read-only contextual datasets identified by URIs and selected by the user.

Q4: Security

Environment Variable Injection

Question: Why avoid hardcoded tokens and how does Claude pass them?

Verified Answer: Hardcoding risks repository leaks. Claude Desktop injects secrets through the `"env"` block in `claude_desktop_config.json`, which passes keys securely into the server process.

Q5: Data Integrity

ACID Atomicity & Rollback

Question: Why is transactional rollback critical during tool crashes?

Verified Answer: Without rollback, mid-execution crashes leave corrupted or duplicate records in the database. `conn.rollback()` satisfies Atomicity ("All or Nothing"), restoring clean state.

Q6: Multi-Server

Orchestration & Chaining

Question: Can Claude coordinate multiple MCP servers in a single prompt?

Verified Answer: Yes. Claude Desktop starts all configured servers, merges their tools into a unified registry, and allows the LLM to chain calls (e.g. read from Leave server, write to GitHub server).

Q7: Resilience

Graceful Error Strings vs. Exceptions

Question: Why return friendly text instead of unhandled exceptions?

Verified Answer: Unhandled exceptions crash the JSON-RPC pipe and halt the reasoning chain. Returning a clean error string allows the LLM to inspect the failure, self-correct, or inform the user politely.

Q8: Workflows

The MCP Prompt Primitive

Question: What is an MCP Prompt and why use it?

Verified Answer: MCP Prompts provide standardized, reusable company prompt templates with parameters, ensuring reliable and structured LLM outputs every time.
